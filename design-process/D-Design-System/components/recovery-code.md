# Recovery Code Display [txt-101]

**Type:** Content
**Category:** Text (one-time secret display)
**Purpose:** Show an Owner's one-time recovery code exactly once, grouped so it is easy to copy or write down, with a Copy button, a plain "not shown again" warning and an "I have saved it" step.

---

## Overview

The recovery code is the Owner's only way back in after a forgotten password (no SMS, no support desk; FR-54). Mojud stores only its hash, so the code can be shown **once**: at sign-up, after a recovery, and after the Owner makes a new code in Settings. The Recovery Code Display is the shared block used in all three places:

1. **Heading** (and, after recovery, a done line).
2. **Explanation**: what the code is for and where to keep it.
3. **Code box**: 16 characters in 4 groups of 4 ("K7QM 2XRD 9PLA WF3T"), selectable as one block.
4. **Copy code** button, with "Copied" feedback or a fallback sentence when the clipboard is blocked.
5. **Warning notice**: "It will not be shown again…".
6. **I have saved it** primary button, always enabled.
7. **Leave guard**: a dialog (in-app) or the browser prompt (tab close / reload) if the Owner tries to leave before "I have saved it".

Page specs call it "recovery-code display" ([09.1 Open Question 6](../../C-UX-Scenarios/09-haque-sets-up-his-business/09.1-sign-up/09.1-sign-up.md)); the shared pattern is written out in [11.1 → Section: View B](../../C-UX-Scenarios/11-haque-recovers-his-account/11.1-owner-recovery/11.1-owner-recovery.md).

The **code entry field** on 11.1 (`recovery-code`, `autocomplete="one-time-code"`) is not this component; it is an [Input Field](./input-field.md).

## States

**Required States:**

- shown (default)
- copied
- copy failed
- leave attempt

**Optional States:**

- focus (Copy, I have saved it)
- hover
- dismissed (after "I have saved it")

**State Descriptions:**

| State | Appearance and behaviour |
|---|---|
| **Shown** | Heading focused; code box on `surface-alt` with 1px `control-border`; Copy code (secondary); warning notice with 4px `warning` left bar; I have saved it (primary, full width). |
| **Hover** | Buttons follow [Button Secondary](./button-secondary.md) / [Button Primary](./button-primary.md). The code box has no hover state (it is not a control). |
| **Focus** | [Focus Ring](./focus-ring.md) on Copy and I have saved it. |
| **Copied** | Copy button label becomes "Copied" with the success check icon for 5 s, then returns to "Copy code"; the polite region announces "Copied". The button stays usable. |
| **Copy failed** | Clipboard blocked: the sentence "Couldn't copy. Select the code and copy it, or write it down." appears under the button in `body`, `danger`. The code stays selectable. |
| **Leave attempt** | In-app navigation (a link, a tab, Android Back in an installed PWA) before "I have saved it" opens a [Confirmation Dialog](./confirmation-dialog.md) "Leave without saving the code?" with Go back (initial focus) and Leave. Closing the tab or reloading triggers the browser's own "leave page?" prompt. |
| **Dismissed** | After "I have saved it" the code is cleared from memory; it can never be shown again. Back / reload never shows it (`Cache-Control: no-store`). |

There is no loading state inside the component (the code is generated by the triggering action, which shows its own spinner), no disabled state ("I have saved it" is always enabled because Mojud cannot check where the code was saved), and no offline state (once shown, Copy and continue work offline).

## Behavior

### Interactions

**On appear:** Focus moves to the heading. The polite region announces the ready / done line once ("{business} is ready." / "Your new password is set…").

**Copy code:** Copies the dashed form "K7QM-2XRD-9PLA-WF3T" (dashes between groups) to the clipboard. Success → "Copied" for 5 s. Failure → fallback sentence. No toast.

**Select:** The code box text is selectable as one block (one triple-click / long-press selects all 16 characters and the group spaces).

**I have saved it:** Always enabled. Sign-up and recovery: replace the history entry and go to the Owner view, so Back never shows the code. Regenerate: the section returns to its normal view and focus moves to the section heading.

**Leave guard:** As in States. "Leave" discards the code for good; the Owner can make a new one in Settings: Me.

**Code format:** 16 characters from an alphabet without look-alikes (no 0/O, 1/I/L), uppercase, Western digits [ASSUMPTION, 09.1 Open Question 3]. Later entry is accepted case-insensitively with spaces and dashes ignored (EXPERIENCE.md → Accessibility Floor).

**Security (NFR-6):** Never in the URL, page title, logs, analytics or browser storage; cleared from memory after "I have saved it" or leaving; page served with `Cache-Control: no-store`.

### Animations

None. The "Copied" label swap is instant.

## Accessibility

**ARIA Attributes:**
- Code box: `role="group"` with accessible name "Recovery code" / "রিকভারি কোড"; each group is a `span`. Not an input.
- Provide a visually hidden spelled-out version for screen readers (10.3: "visually hidden spelled-out version") and mark the visual groups `aria-hidden="true"` so the code is not read twice [see Open Question 3].
- Copy button: name "Copy code"; after copy the visible label "Copied" is the name; result also sent to the polite region.
- Warning notice: plain paragraph with icon `aria-hidden`; not a live region.
- I have saved it: plain button (no `aria-disabled`, always enabled).
- Leave dialog: `role="alertdialog"`, initial focus Go back, Escape = Go back.

**Keyboard Support:**
- Tab: heading (programmatic focus only) → Copy code → I have saved it.
- Enter / Space: activate buttons.
- Escape in leave dialog: Go back.

**Screen Reader:**
Reads the heading, the explanation, then "Recovery code, K 7 Q M, 2 X R D, 9 P L A, W F 3 T" group by group, with character-by-character reading available. "Copied" announced politely.

**Never color alone:** warning = icon + bar + words; copied = check icon + word.

**Language:** The code itself has no language and must not be read as Bangla words; mark the code box `lang="en"` [see Open Question 4].

- One language per User. Explanation and warning are plain, no blame.
- **No glyphs**: name places in words ("My settings"), never with an arrow ("Settings → Me" in 09.1 must change; 11.1 Open Question 7).
- Western digits in the code and dates.
- The code is never translated, never in Bangla digits.

## Usage

### When to Use

- Any time a recovery code is created: sign-up, after recovery, Make a new recovery code.

### When Not to Use

- Typing a code in: use [Input Field](./input-field.md) with `autocomplete="one-time-code"`.
- Temporary passwords for staff (09.6 "Pass it on"): different secret, different rules (shown to the admin to hand over).

### Best Practices

- Show it once, then forget it on the client.
- Keep "I have saved it" enabled; do not add fake checks.
- Name the place to make a new code in words.
