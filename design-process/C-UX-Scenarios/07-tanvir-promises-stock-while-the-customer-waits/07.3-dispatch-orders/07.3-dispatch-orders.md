## Overview

**Page Purpose:** Turn a promise into Reserved stock: create a Dispatch order for **one Warehouse** with a customer name, Products, quantities and a required date, never more than the Promisable quantity; then list, reduce or cancel open orders, releasing stock back to Available (FR-23, FR-24).

**User Situation:** Tanvir is still on the call. From the Narayanganj ladder he opened a new order with Rice 25 kg and Narayanganj filled in. He needs 50 cartons; Narayanganj can give 32. He types 50, sees "Only 32 ctn available. Max 32 ctn.", taps Use max, saves, then creates a second order for the other 18 from Gazipur. Before he hangs up both are saved and no colleague can promise those 50 cartons again (UJ-4 steps 3-5, scenario Q7).

**Success Criteria:**
- The maximum is visible **before** he types ("Max 32 ctn"), and any higher number is refused in his units with a one-tap fix (Use max) (FR-13, FR-23; Voice and Tone).
- Each order holds exactly one Warehouse (FR-23); a second Warehouse means a second order, and the screen makes that easy (pre-filled customer and date).
- On save, "Saved · DO-1043" shows and Promisable drops at once everywhere (the 32 are Reserved) (UJ-4 climax).
- Reduce and cancel return the released quantity to Available, with cancel confirmed once (FR-24; Interaction Primitives → Confirm vs undo).
- No taka on this surface: Mojud stores no selling prices (FR-6), and Sales reps never see Stock value (DD-2).

**Entry Points:**
- "Create Dispatch order" on a Warehouse ladder in [07.2 Product stock](../07.2-product-stock/07.2-product-stock.md): Create form with Product + Warehouse pre-filled (this scenario).
- Orders tab → Dispatch orders segment (Sales rep: the only segment) → List. Owner on phone: the Orders tab (Overview · Issues · Stock · Orders · More, DD-9). Manager on phone: More → Orders, the first item in More (DD-9). Desktop: side-nav "Orders" for all three Roles.
- Issues: a Dispatch-short Issue on the Sales rep's own order links to its detail ([03.2](../../03-nasima-clears-the-inbox/03.2-issue-detail/03.2-issue-detail.md)).

**Exit Points:**
- Save order → Order detail with toast; "Create another order for {customer}" → a new Create form (UJ-4 step 4).
- Back from Create → the page it came from (07.2), with a discard check only if something was typed.
- Product line name → [07.2 Product stock](../07.2-product-stock/07.2-product-stock.md).
- Scenario end: both orders saved; Promisable on 07.1 / 07.2 shows Narayanganj 0, Gazipur 2.

## Technical Notes

- **Reservation (FR-23):** saving the order records one Stock movement per line, Available → Reserved, at the order's Warehouse, with the User, time, Reason and a link to the order (FR-11). The server re-checks Promisable at save (FR-13, NFR-4) and refuses the whole order if any line is over; the response carries each over-line's current max.
- **Reduce / cancel (FR-24):** Reserved → Available for the released quantity; only while not dispatched; only by the creator, a Manager or the Owner (server-enforced, FR-4).
- **One Warehouse per order (FR-23):** the form holds one; a second needs a second order.
- **Duplicate safety (FR-14):** device-generated action ID on Save order, Save changes and Cancel.
- **Units (FR-9):** entered as cartons + pieces, stored in Base units, shown as Pack + leftover Base.
- **No money:** Mojud stores no selling prices (FR-6); the order shows no taka for any Role (DD-2 for Sales rep).
- **Offline:** creating and changing orders is online only (FR-41 lists only floor actions); the controls are disabled with "Needs internet".
- **Accessibility:** form errors use `aria-invalid` + `aria-describedby` to the Refusal; Refusals go to the assertive region once per change; toasts to the polite region. Save stays focusable when disabled with its reason in the description. Focus after save → the detail H1; after "Use max" → the carton field; dialog focus on Go back and return on close.
- **URL state:** `/orders/dispatch?status=open`, `/orders/dispatch/new?warehouse=…&product=…`, `/orders/dispatch/{id}`.
