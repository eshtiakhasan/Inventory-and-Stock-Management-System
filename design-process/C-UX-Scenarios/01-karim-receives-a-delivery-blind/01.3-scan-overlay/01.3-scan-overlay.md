## Overview

**Page Purpose:** Identify a Product by its Barcode with the phone camera, or by typed code / search, and hand the match back to the screen that opened the overlay. **A scan only identifies and pre-fills; it never records**, except in Flag damage mode (Interaction Primitives → When does a scan record).

**User Situation:** Karim is on Receive PO with a carton of Rice 25 kg in his hand. He taps the Scan bar, points the phone at the carton's Barcode, and wants to land on the Rice line with the carton field ready for his count. The first time on this phone, Chrome asks for camera permission.

**Success Criteria:**
- A readable Barcode is matched in under 1 s (NFR-1) and the overlay closes on the matched line; no extra tap.
- "Type code" is always visible, so a damaged label or a refused camera never blocks the task (FR-39).
- Offline, a Barcode not in the phone's catalogue says "Not on this phone yet" and records nothing.
- Close always returns to exactly where he was, with nothing changed.

**Entry Points:**
- Scan bar on floor screens: [01.1 My tasks](../01.1-my-tasks/01.1-my-tasks.md), [01.2 Receive PO](../01.2-receive-po/01.2-receive-po.md), S6, [02.1 Pick](../../02-karim-picks-and-flags-damage/02.1-pick-dispatch-order/02.1-pick-dispatch-order.md), [05.2 Send](../../05-karims-transfer-arrives-short/05.2-send-transfer/05.2-send-transfer.md) / [05.3 Receive Transfer](../../05-karims-transfer-arrives-short/05.3-receive-transfer/05.3-receive-transfer.md), [08.2 Count lines](../../08-rafiq-runs-the-weekly-count/08.2-count-lines/08.2-count-lines.md).
- Scan tab in the bottom tab bar. This is the only way in from desk-role home screens (Issues inbox, Owner view, Product search for Sales rep), which have no fixed Scan bar (DD-4).
- Scan icon button in a Product search field (S5, S14, S24).
- Flag damage button (opens **Flag damage mode**; specified in [02.2 Flag damage](../../02-karim-picks-and-flags-damage/02.2-flag-damage/02.2-flag-damage.md)).

**Exit Points (by context):**

| Opened from | On a match | Then |
|-------------|-----------|------|
| Receive PO (S7), Receive Transfer (S10), Count lines (S11), blind | Overlay closes; line selected; unit from the Barcode; quantity **empty**; unit field focused | Karim types 92 and taps Save line on [01.2](../01.2-receive-po/01.2-receive-po.md); repeats; Mark delivery complete |
| Pick Dispatch order (S8) | Line selected; full remaining quantity pre-filled | Confirm line (02.1) |
| Send Transfer (S10 send) | Line added or selected; quantity empty | Save line (05.2) |
| My tasks, Scan tab, S5, S6 (no mode) | Opens Product stock (S6) for that Product | — |
| A Product field (S14, S24, search) | Fills the field | The form's own save |
| Flag damage mode | **The scan saves** 1 of the scanned unit as damaged | Toast with Change qty/reason (02.2) |

Close / Escape / Back → returns to the opener, nothing changed, focus back on the control that opened the overlay.

## Layout Structure

Full screen over the current page. Camera feed fills the screen; edges under `scrim-dark`. A one-line hint strip sits above a rounded viewfinder in the upper middle. The bottom third is a `surface` action bar with two side-by-side 64px buttons (Close, Type code), each at least 9rem wide; they stack at 320 CSS px or text ≥ 150%. No torch control in v1. Type code replaces the camera view with a search field and results in the same overlay.

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Permission prompt | First Scan bar tap on this phone/browser | Chrome's permission prompt over the overlay; hint visible behind | Allow → camera; Block → Camera not available state |
| Camera live (default) | Permission granted | Feed, viewfinder, "Point at the barcode", Close + Type code | Scan, Type code, Close |
| Slow read | ~8 s with no read | Hint "Can't scan? Type the code." | Type code, Close |
| Matched | Barcode read and matched | Vibration, overlay closes, opener updates (blind: line selected, quantity empty, unit field focused); announcement | Continue on opener |
| Not on this phone yet | Offline + Barcode not cached | Warning message panel; camera stays live | Scan again, Type code, Close |
| Not found | Online + unknown Barcode | Danger panel + Search; Manager/Owner also Link this barcode | Search, Close |
| Not in this task | Known Product not on the open task | Info panel "Not on this delivery"; nothing recorded | Scan again, Close |
| Camera not available | Denied, unsupported, no HTTPS | Opens in Type code mode with the explanation line, field focused | Type, choose, Close |
| Type code | Type code tapped | Heading, field, results while typing | Choose result, Close |

## Technical Notes

- **HTTPS required** for camera access (addendum). Use the browser's barcode detection where present, otherwise a JS decoder; the choice is architecture's.
- **Permission timing:** call `getUserMedia` only after the user taps the Scan bar or Scan tab, never on load.
- **Camera lifecycle:** stop all tracks on match, Close, route change and `visibilitychange` (battery on low-cost phones).
- **Unit from Barcode:** Pack-unit Barcode → carton row, Base-unit Barcode → piece row (FR-38).
- **Context contract:** the opener passes a context (`blind-receive`, `pick`, `send-transfer`, `count`, `product-field`, `none`, `flag-damage`) and the task's Product IDs; the overlay returns the matched Product + unit. The overlay itself never records, except `flag-damage`.
- **Blind safety:** in blind contexts the overlay never receives or renders quantities.
- **Count blinding (DD-7):** the server withholds On hand, Promisable, ladder, movement quantities and low-stock status for Products in an open count at that Warehouse from Users assigned to count it; the overlay renders "Hidden during count". The cached offline catalogue must not hold those figures for those Products either.
- **Alternate names (DD-10):** search indexes main name, Alternate names (up to 5 per Product `[ASSUMPTION]`), SKU and Barcode, online and in the cached catalogue.
- **Focus:** dialog heading on open; opener's control on close; Type code field when Type code opens.
- **Offline catalogue:** Products, Barcodes, Pack units and Conversion factors are cached (EXPERIENCE.md → Foundation).
