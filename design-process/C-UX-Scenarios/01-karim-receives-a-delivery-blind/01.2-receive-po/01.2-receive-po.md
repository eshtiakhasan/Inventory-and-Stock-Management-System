## Overview

**Page Purpose:** Let the worker count a supplier delivery line by line **without ever seeing the ordered or outstanding quantity**, save each count under his name, and close the delivery with one confirm (FR-21, FR-22).

**User Situation:** Karim has just tapped the Purchase order card. The truck is backed in, the driver is waiting, and signal at the back of the warehouse comes and goes. He wants to count fast and be sure each count is kept even if the network drops.

**Success Criteria:**
- He receives a line with scan + count + one tap on Save line (blind exception to NFR-2).
- No ordered, expected, outstanding or system quantity appears anywhere: on screen, after save, in the dialog, in `aria-*` attributes, hidden text or page code (State Patterns → Blind).
- Each save shows "Saved" (online) or "Saved on phone, will sync" (offline) and the line shows "Counted {qty}".
- Mark delivery complete is available at any time and confirms in one dialog that counts lines, never quantities.
- After confirming he lands on My tasks with "Receipt saved" and the next task; any Shortfall goes to a Supervisor, never to his screen (UJ-1 step 6, FR-22).

**Entry Points:**
- PO task card on [01.1 My tasks](../01.1-my-tasks/01.1-my-tasks.md).
- Back from [01.3 Scan overlay](../01.3-scan-overlay/01.3-scan-overlay.md) (Close, no change) or after a successful scan (line selected).
- (Manager / Owner) from a Purchase order in S15. [Out of this scenario]

**Exit Points:**
- Scan bar → [01.3 Scan overlay](../01.3-scan-overlay/01.3-scan-overlay.md) (scenario's next step).
- Mark delivery complete → confirm → [01.1 My tasks](../01.1-my-tasks/01.1-my-tasks.md) with "Receipt saved" and the next task.
- Offline banner → [01.4 Offline queue](../01.4-offline-queue/01.4-offline-queue.md).
- Back (app bar) → My tasks, nothing lost: saved lines stay saved (their stock has already moved, DD-1), the task shows "In progress".

## Technical Notes

- **Blind is a data rule, not only a UI rule:** the S7 client payload must not contain ordered, outstanding or received-by-others quantities, including in cached offline data, `aria-*`, hidden text and analytics events (State Patterns → Blind).
- **Action IDs:** every Save line and the completion carry a device-generated unique ID (FR-14); double taps and offline retries apply once.
- **Offline:** Save line and Mark delivery complete queue (FR-41) with original device time; server time added on sync (FR-43). The dialog's line count is computed on the phone.
- **Stock posting (DD-1):** each Save line is its own Stock movement (Receipt line into Available). Mark delivery complete closes the task and raises Shortfall / Over-delivery Issues; it posts no movement for lines already saved.
- **Units:** stored in Base units; displayed as Pack + leftover Base units (FR-9). Conversion factor comes from the cached catalogue.
- **Live regions:** toast and scan match to polite; any server refusal to assertive, once.
- **Focus management:** after a scan, focus to the focused unit field; after save, to the Scan bar; dialog initial focus on Go back and focus return on close.
- **Scroll padding** keeps the focused field and Save line clear of the app bar, the fixed zone, the keyboard and the toast.
- **Who / when / where** recorded on every line (SM-3).
