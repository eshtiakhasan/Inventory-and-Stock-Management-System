## Overview

**Page Purpose:** Let the Owner or Manager add, rename and deactivate the Business's Warehouses, at most 3 active (FR-10), and see clearly how many of the 3 are used.

**User Situation:** Mr. Haque has just signed up and sees the setup checklist on the Owner view. Step 1 is "Add warehouses". He adds Narayanganj and Gazipur in under a minute, then follows the checklist on to Excel import. Hope: real stock by Saturday morning. Worry: entering everything twice.

**Success Criteria:**
- Adding a Warehouse takes one button, one name and Save (Enter works).
- The page always says how many of the 3 are in use ("2 of 3 active warehouses").
- A 4th Warehouse is impossible to start by mistake: the Add button is disabled with a visible reason, and a raced attempt is refused with a sentence naming the limit of 3 (FR-10, UJ-8 failure path).
- Deactivating a Warehouse with stock is refused with the reason and what to do instead (FR-10).
- From here he can continue setup without hunting: a "Next: Import products from Excel" link sits on the page while the Business is in first use.

**Entry Points:**
- [04.1 Owner view](../../04-haque-traces-an-unexplained-loss/04.1-owner-view/04.1-owner-view.md) first-use checklist → "Add warehouses" (`owner-view-first-use-steps-warehouses`).
- Side nav "Settings" (desktop) → Settings section links → "Warehouses".
- Phone / tablet: More → Settings → Warehouses.
- Deactivation refusal links from other Settings pages (none in v1).

**Exit Points:**
- Setup strip "Next: Import products from Excel" → [09.3 Settings: Excel import](../09.3-settings-excel-import/09.3-settings-excel-import.md) (UJ-8 step 5). Scenario exit: he goes on from the setup checklist.
- Setup strip "Back to setup list" → [04.1 Owner view](../../04-haque-traces-an-unexplained-loss/04.1-owner-view/04.1-owner-view.md).
- Settings section links → other Settings pages.
- Side nav / tab bar → any other surface.

## Shared Settings layout

Used by S22–S26 (pages 09.2–09.6). Each Settings page spec lists only its differences.

### Frame

- **App bar** ([app-bar](../../../D-Design-System/components/app-bar.md)): sticky, min `{spacing.app-bar-height}`. Left: screen title on phone/tablet. Right: Business name (desk screens), signed-in User's name in `body`, online status as icon + text ("Online" / "Offline"), never a dot alone. Same as [04.1 `owner-view-app-bar`](../../04-haque-traces-an-unexplained-loss/04.1-owner-view/04.1-owner-view.md).
- **Desktop (≥ 1024px):** [side-nav](../../../D-Design-System/components/side-nav.md) (13.75rem) with **Settings** current (`aria-current="page"`). Owner and Manager items: Overview · Issues · Stock · Orders · Counts · Settings (EXPERIENCE.md IA table).
- **Phone and tablet (< 1024px):** [bottom-tab-bar](../../../D-Design-System/components/bottom-tab-bar.md). Owner: Overview · Issues · Stock · Orders · More (DD-9); Manager: Issues · Stock · Counts · More, with Orders as the first item in More (DD-9). Settings is reached through **More → Settings**, and More is the active tab.
- **No Scan bar** on any Settings page (DD-4: the fixed Scan bar is on floor screens only). Barcode fields use a scan icon button instead (09.4).
- **Skip link** "Skip to content" first; landmarks `nav`, `main`, and `aside` for the desktop detail panel; one H1 per page; focus to the H1 after a route change (EXPERIENCE.md → Desk structure).

### Settings header

- **H1** page title in `headline` (e.g. "Warehouses"), then a one-line description in `body`, `text-muted`.
- **Settings section links** ([section-nav](../../../D-Design-System/components/section-nav.md) → `links row`, Open Question 1): a row of links under the H1 on tablet and desktop, in this order: **Warehouses · Products · Suppliers · Excel import · Users · Me**. The order follows the setup checklist on 04.1. Each link is ≥ `{spacing.target-min}` tall, `primary` text in `body`; the current one is `body-strong` with a 3px `primary` bottom bar and `aria-current="page"` (selection by bar + weight, not color alone). Links wrap to a second line, never scroll sideways.
- **Phone:** no section links row. More → Settings opens a **Settings index** (a list of 48px rows with chevrons, same order, plus "Me"); each Settings page has a **Back** button "Settings" at the left of the app bar that returns to the index with scroll kept.
- **Role visibility:** Owner and Manager see all six links; every other Role sees only "Me", and More → Settings opens [10.3 Settings: Me](../../10-karim-signs-in-on-the-shared-phone/10.3-settings-me/10.3-settings-me.md) directly. Deep links to a hidden Settings page show "You don't have access to this."

### Setup strip (first use only)

- Shown on Settings pages and Excel import while the Business is in **first use**, using the same rule and step order as the 04.1 checklist (first use lasts until opening stock exists; a step is Done when at least one record of that kind exists; 04.1 Open Question 7).
- Content: "Setting up · step {n} of 5" in `body-strong`, then "Next: {next step}" as a text link to the next not-done step, and "Back to setup list" as a text link to 04.1. Steps and their strings are the 04.1 keys `owner.firstUse.step.*`.
- Style: `surface-alt` band, `{rounded.md}`, padding `{spacing.3}` `{spacing.4}`, info icon; all links ≥ `{spacing.target-min}`. Not sticky. Disappears for good once first use ends.

### List + detail body

- **Toolbar** above the list: primary "Add {thing}" button ([button-primary](../../../D-Design-System/components/button-primary.md), min `{spacing.button-desk}`) at the end of the row on desktop, full width at the top on phone; search field and filter chips where the page has them (09.4, 09.5, 09.6).
- **Settings list** ([data-table](../../../D-Design-System/components/data-table.md), Open Question 2): rows on `surface`, 1px `border` dividers, min `{spacing.target-min}` (64px when two lines). Desktop shows column headers (`body-strong`, `text-muted`) and a real `<table>` with a row header cell per record; the whole row's name cell is a link that opens the detail. Phone shows the same rows as stacked two-line items (name in `title`, facts in `meta` / `meta-bn`), still one link per row. Status uses the [task-status-tag](../../../D-Design-System/components/task-status-tag.md) look, display only.
- **Detail panel:** desktop (≥ 1024px): a right-hand `aside` using the [drill-down-panel](../../../D-Design-System/components/drill-down-panel.md) frame (`surface`, 1px `border` left edge), min 26rem, holding the create / edit form; the list stays visible and the selected row gets a 4px `primary` left bar + `surface-alt` fill (plus visually hidden "Selected"). Tablet and phone: the form is its own full-screen view (a real history entry) with a Back button; Android / browser Back returns to the list with scroll kept.
- **URL state:** `/settings/{section}`, `/settings/{section}/new`, `/settings/{section}/{id}`.
- **Form pattern:** labels above fields in `body-strong`; optional fields say "(optional)" after the label; helper text in `meta` / `meta-bn` under the field; inline errors under the field in `body-strong` `danger` with an alert icon and a 2px `danger` field border. On submit with 2+ errors a [form-error-summary](../../../D-Design-System/components/form-error-summary.md) ([refusal-message](../../../D-Design-System/components/refusal-message.md) tokens) appears at the top of the form and takes focus; its links move focus to each field. With 1 error, focus goes to that field. Buttons at the end of the form: desktop right-aligned, **Cancel** ([button-secondary](../../../D-Design-System/components/button-secondary.md)) then **Save** ([button-primary](../../../D-Design-System/components/button-primary.md)) rightmost; phone full width, stacked, Save at the bottom. Enter saves (EXPERIENCE.md → Keyboard). Destructive actions (Deactivate, Archive) sit in a separate plain section at the very end of the edit form (no red "danger zone" styling), as a [button-secondary](../../../D-Design-System/components/button-secondary.md), and always open a [confirmation-dialog](../../../D-Design-System/components/confirmation-dialog.md) with a `danger` confirm.
- **Saving:** spinner inside Save, label "Saving…", `aria-disabled`, fields read-only, one request (FR-14). Success: [confirmation-toast](../../../D-Design-System/components/confirmation-toast.md) "Saved" (or a specific line) with the success icon, the list row updates, focus returns to the row that was edited (or the new row). On desktop the panel closes after Save [ASSUMPTION].
- **Unsaved changes:** Cancel, Back or opening another row with changed fields shows a [confirmation-dialog](../../../D-Design-System/components/confirmation-dialog.md) "Discard changes?" with "Keep editing" (Go back) and "Discard" (danger) (Open Question 5).
- **Offline:** list shows last loaded data with "as of HH:MM (offline)"; Add and Save become [button-disabled](../../../D-Design-System/components/button-disabled.md) with "Needs internet" visible beside them (EXPERIENCE.md → State Patterns → Offline: settings need a connection).
- **Loading:** skeleton rows in the shape of the list (`aria-busy="true"`); last loaded data shows at once with "as of".
- **Error:** "Couldn't load {things}. Try again." + Try again; save errors keep typed values: "Couldn't save. Try again."
- **Toasts** float at the bottom of the content area (above the tab bar on phone), never cover the focused element, 5 s.

- **Valid:** Save enabled.
- **Invalid:** field error shown; Save stays enabled and re-runs validation, moving focus to the error summary (2+ errors) or to the field (1 error) (no dead button), except for the server limit refusal, where Save is `aria-disabled` with the reason.

## Technical Notes

- **Permissions (FR-4):** Owner and Manager only, enforced on the server; hidden elsewhere.
- **Limit (FR-10, NFR-10):** the server checks "fewer than 3 active" atomically on create and reactivate (NFR-4: two admins adding at once cannot make 4). The UI state is a hint only.
- **Deactivation (FR-10):** refused while any On hand quantity exists. Deactivated Warehouses disappear from Warehouse pickers (PO, Dispatch order, Transfer, Stock count, Users' Assigned Warehouses) but stay in history, filters and the owner view's past months.
- **Names** are shown exactly as entered and never translated (FR-45).
- **First-use rule:** the setup strip reads the same server flags as the 04.1 checklist so both always agree.
- **Focus:** route change → H1; form open → form title (then first field on Add); Save → the row; dialog → Go back; dialog close → the Deactivate button or the limit line after success.
- **Live regions:** polite for toasts and the limit line; assertive for refusals (once per change).
- **Reflow:** 320 CSS px and 400% zoom; the desktop table becomes stacked rows below 600px; long Bangla labels wrap.
- **No Scan bar** (DD-4); no offline queue for settings (EXPERIENCE.md → State Patterns → Offline).
