## Overview

**Page Purpose:** Let an Owner who forgot his password get back in by himself, with no SMS and no support desk: phone number + recovery code + new password; then show a new recovery code exactly once, because the old one has just been used up (FR-54, SM-7).

**User Situation:** Mr. Haque, a month into the pilot, on a new phone; the old one held his saved password. It is evening; he wants to check today's losses. Hope: get back in tonight without asking anyone. Worry: losing access to his business data for good.

**Success Criteria:**
- From Sign in, one tap on "Owner? Use your recovery code" brings him here with his phone number already filled if he had typed it.
- He can paste or type the code in any case, with or without spaces or dashes.
- A wrong code or number is refused with one calm sentence that does not say which part was wrong.
- He sets a new password (his password manager can save it), sees a new recovery code once, copies it, taps "I have saved it", and lands on the Owner view ([04.1](../../04-haque-traces-an-unexplained-loss/04.1-owner-view/04.1-owner-view.md)), signed in.
- He is told plainly that the old code no longer works.

**Entry Points:**
- [10.1 Sign in](../../10-karim-signs-in-on-the-shared-phone/10.1-sign-in/10.1-sign-in.md) → "Owner? Use your recovery code" (carries the typed phone number and the language).
- Direct link to the recovery route (bookmarked or typed).

**Exit Points:**
- View B "I have saved it" → [04.1 Owner view](../../04-haque-traces-an-unexplained-loss/04.1-owner-view/04.1-owner-view.md), signed in as Owner (history entry replaced, so Back cannot show the code again).
- View A "Back to sign in" → [10.1 Sign in](../../10-karim-signs-in-on-the-shared-phone/10.1-sign-in/10.1-sign-in.md).

**Short screen / landscape / text ≥ 150%:** app bar compacts; nothing else fixed; code groups wrap; buttons stay full width.

## Technical Notes

- **One transaction (FR-54):** verify phone + code (Owner Role, active code) → set the new password hash → cancel the old code → generate and hash the new code → sign this device in → end other sessions [ASSUMPTION]. If any step fails, nothing changes and the old code still works.
- **Code format and storage:** 16 characters, 4 groups of 4, uppercase, no look-alikes [ASSUMPTION, shared with 09.1]; stored only as a hash (NFR-6); compared after removing spaces and dashes and upper-casing (Accessibility Floor).
- **Enumeration safety:** the same refusal for unknown numbers, non-Owners, wrong codes and used codes; the pause applies per phone number whether or not an account exists; similar response time for all refusals.
- **Attempt counting:** a separate counter from sign-in, with the same 5-tries / 15-minutes rule [ASSUMPTION; Open Question 4].
- **View B safety:** `Cache-Control: no-store`; the code is never cached by the service worker, never put in storage, URL, title, logs or analytics; cleared from memory on leaving; `location.replace` to the Owner view after "I have saved it" (as 09.1).
- **Offline:** recovery always needs internet; the PWA shell still opens this page offline so the "Needs internet" state can be shown.
- **Language:** carried from 10.1 (or the device's last language); after success the Owner's saved language applies from View B on (10.1 decision L4).
- **Live regions:** polite (online status, done line, copy result) and assertive (refusals) regions exist from page load.
