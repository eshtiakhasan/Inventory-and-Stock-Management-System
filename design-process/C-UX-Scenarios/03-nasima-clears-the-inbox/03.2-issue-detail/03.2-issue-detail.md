## Overview

**Page Purpose:** Show the full evidence and history of one Issue, then let an eligible User take one of the decisions fixed for its type (FR-33a), add a comment (FR-32), or, as Owner / Manager, assign it to an eligible User (FR-33).

**User Situation:** In UJ-3, Nasima has approved the first Damage flag from its card and opens the second flag to look before deciding: who flagged it, how much, where, when. She sees the carton was fine and rejects it. The same page serves Mr. Haque assigning a Discrepancy case to the Manager from the owner drill-down (04) and Rafiq, the Manager, resolving count cases as Found or Confirmed loss (08).

**Success Criteria:**
- The evidence answers "what, how much, where, who, when" without leaving the page; for two-party Issues it shows **both** counts, **both** Users and **both** times (FR-28, FR-37).
- Every decision for the type is visible, each labelled with its effect on stock ("Reject · back to Available"); one tap decides, except decisions that need a choice, which open one small picker (Found → Warehouse; Confirmed loss → Reason).
- The decision is recorded with User, time, Warehouse, Reason and comment (NFR-5) and the User returns to the inbox with the Issue gone.
- The User is never stuck: segregation of duties, already decided, offline and refusals each say what happened and what next.

**Entry Points:**
- 03.1 Issues inbox: card title link, or "Open to decide".
- Owner view drill-down row (S18, scenario 04).
- Stock counts close → inbox → "Open to decide" (scenario 08).
- My record linked case row (S20, UJ-9; read-only).
- Sync-status chip "Not applied – sent to supervisor" (S21 / S20; read-only for the worker).

**Exit Points:**
- After a decision: back to the list it came from (03.1, or S18 drill-down) with scroll kept; on desktop the pane loads the next Issue [ASSUMPTION] and focus stays in the list.
- Back crumb / device Back / Escape (desktop pane: none, list is beside it).
- Links in evidence to the source document (PO, Transfer, Dispatch order, Stock count, Stock movement).
- Recount decisions open a Stock count / receiver task elsewhere (no navigation for the decider).

## Technical Notes

- **One page, twelve variants.** Evidence columns, state pill, decisions and pickers are driven by Issue type (and shortage / surplus for Discrepancy cases); Late count line (DD-6) and Draft transfer not sent (DD-5) are the two added since FR-33a.
- **Raised by the server:** a Late count line Issue is raised for the Manager who started the count when a count line syncs after Close count (DD-6); a Draft transfer not sent Issue is raised for the source Supervisor 24 h after a draft's first saved line `[ASSUMPTION: 24 h]` (DD-5). Both rank by ৳ like any Issue (DD-2: draft value = draft quantity × Unit cost; late line value = difference × Unit cost) [ASSUMPTION]. FR-33a is the source of truth; the server returns the allowed decisions for this User and Issue, the client never computes eligibility.
- **Server checks on every decision:** FR-4 role and Warehouse, FR-5 segregation (with Owner exception flag), FR-13 no-negative, NFR-4 already-decided. The response carries the outcome the page renders.
- **Value display (DD-2):** the server sends the ৳ amount only to Roles with View Stock value (FR-4); other payloads carry quantity and unit only.
- **Audit (NFR-5):** decision records User, time (device + server), Warehouse, Reason (where the decision has one) and the comment. Nothing is editable afterwards; mistakes go through Reversal (FR-15).
- **Duplicate safety (FR-14):** decision, assign and comment each carry a device-generated action ID.
- **No offline decisions** (State Patterns → Offline, Decided). The evidence of Issues already listed in 03.1 is cached for reading [ASSUMPTION: cache scope].
- **Focus:** phone route change → focus to H1; sheets trap focus and return it; after "Already decided" focus moves to the notice. Desktop pane: focus stays in the list after a decision; the removal is announced.
- **Live regions:** decision results and assign go to the polite region; refusals to the assertive region, once per change.
- **Reflow:** evidence columns stack at 320 CSS px / 150% text; decision buttons always full width; the dock un-fixes on short screens. Works at 400% zoom with no loss.
- **Recount decisions** create work elsewhere (receiver recount task for Transfer overage; a one-Product Stock count for Sync conflict and for Late count line "Start recount"). Where that task appears is outside this page [see Open Questions #10].
- **Photos:** FR-29 makes photo upload SHOULD, not v1; the outline's "photo if any" is not designed in v1.
