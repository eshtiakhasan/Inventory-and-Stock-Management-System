## Overview

**Page Purpose:** Make the User replace the temporary password, which the Owner or Manager knows and wrote on a slip of paper, with one only they know, before they see any task, so nothing recorded under their name could have been recorded by someone else (FR-54, SM-3).

**User Situation:** Karim has just signed in on the shared warehouse phone with the temporary password from the slip. He is standing; the phone is in one hand. He wants this done quickly and wants to see his tasks.

**Success Criteria:**
- Karim sees his own name in the app bar and understands why he must set a password, in one sentence.
- He types a new password twice (with an optional Show), taps Save password once, and lands on [10.3 Settings: Me](../10.3-settings-me/10.3-settings-me.md) in its first-sign-in form.
- If the wrong person signed in, one tap on "Not Karim? Sign out" gets them out.
- Mistakes (too short, not matching, same as the temporary one) are explained in one plain sentence each, under the field.

**Entry Points:**
- [10.1 Sign in](../10.1-sign-in/10.1-sign-in.md) with a temporary password (first sign-in after the Owner added the User, FR-3, or after a reset, FR-54).
- Any route while the session still has a temporary password (redirected here).
- Reopening the app on the phone before the password was changed (the session stays in this state).

**Exit Points:**
- Save password succeeds → [10.3 Settings: Me](../10.3-settings-me/10.3-settings-me.md), first-sign-in form (language, install app, then "Go to My tasks"). See Open Question 1.
- "Not {name}? Sign out" → [10.1 Sign in](../10.1-sign-in/10.1-sign-in.md).

Single column; form at the top so both fields and the button stay above the keyboard on a 360×640 phone. No bottom tab bar, no side nav, no Scan bar (DD-4; and the User may not go anywhere else yet). The app bar shows the signed-in name.

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Default (online) | Arrived from 10.1 with a temporary password | Name in app bar; intro; two empty fields with hint; Save enabled | Type, show/hide, save, sign out |
| Loading (saving) | After a valid Save | Button spinner + "Saving…", `aria-disabled`; fields read-only | Wait (< 2 s, NFR-1) |
| Field error | A rule fails (too short, not matching, same as temporary, equals phone number) | Message under the failing field, 2px `danger` border, `aria-invalid="true"`, focus to the first failing field; typed values kept (except: when they do not match, the confirm field is cleared) | Fix and save |
| Offline | No connection | Offline banner; app bar "Offline"; Save disabled (dashed, cloud-off) with "Needs internet" visible; fields still editable | Connect; Save re-enables by itself |
| Error (server) | Save fails for an unknown reason | Form message "Couldn't save the password. Try again."; values kept | Save again |
| Expired session | The temporary-password session timed out before saving (Open Question 4) | Form message "This sign-in has expired. Sign in again." + link to 10.1 | Sign in again |
| Success | Server accepted the new password | Old temporary password stops working; toast "Password saved"; go to [10.3](../10.3-settings-me/10.3-settings-me.md) first-sign-in form | Choose language, install, go to home |
| Shared-phone signed-in name | Always | User name in the app bar from this first screen | "Not {name}? Sign out" |
| Wrong person | Someone signed in with another person's slip | One tap on "Not {name}? Sign out" | Back to 10.1 |
| Dark mode | Device or saved theme | Same layout, `-dark` tokens | Same |

## Form Validation

Rules are shared with [09.1 Sign up](../../09-haque-sets-up-his-business/09.1-sign-up/09.1-sign-up.md) and [11.1 Owner recovery](../../11-haque-recovers-his-account/11.1-owner-recovery/11.1-owner-recovery.md) [ASSUMPTION: no password policy is stated in the PRD; Open Question 3]. No character-class rules (no "must include a number"); length and obvious-reuse checks only.

### Validation Rules

| Field | Rule | Error Code | Error Message (EN) |
|-------|------|------------|---------------|
| `changepw-new` | Required | `ERR_NEWPW_EMPTY` | "Enter a new password." |
| `changepw-new` | At least 8 characters (Unicode characters, spaces count) [ASSUMPTION] | `ERR_NEWPW_SHORT` | "Use at least 8 characters." |
| `changepw-new` | At most 128 characters [ASSUMPTION] | `ERR_NEWPW_LONG` | "Use 128 characters or fewer." |
| `changepw-new` | Not the same as the temporary password (server check) | `ERR_NEWPW_SAME` | "Choose a password different from the temporary one." |
| `changepw-new` | Not the User's phone number in any format (client and server) | `ERR_NEWPW_PHONE` | "Don't use your phone number as your password." |
| `changepw-confirm` | Required; equal to `changepw-new` | `ERR_CONFIRM_MISMATCH` | "The two passwords don't match." |

- **Valid:** Save enabled.
- **Invalid:** errors under fields; Save stays enabled and re-validates on tap (an always-enabled button tells the User what is missing; Refusal-style disabled saves are for quantities).

## Accessibility

| Element | Name / role | Keyboard | Notes |
|---------|-------------|----------|-------|
| `changepw-new` | label "New password"; describedby hint (+ shared-phone hint, + error) | Type | `autocomplete="new-password"`, or `off` on a Shared phone (DD-8); paste allowed |
| `changepw-confirm` | label "Type it again"; describedby error | Type; Enter submits | `autocomplete="new-password"`, or `off` on a Shared phone (DD-8) |
| Toggles | buttons "Show password" with `aria-pressed` | Enter / Space | 48×48; one per field, each names its own field in its description (`aria-describedby` to the field label) |
| `changepw-submit` | button "Save password" | Enter / Space | `aria-disabled` + describedby "Needs internet" when offline |
| `changepw-signout-link` | button "Not Karim? Sign out" | Enter / Space | 48px row |
| Errors | text linked by `aria-describedby`; first error announced in the assertive region | — | Never color alone: alert icon + text + border |

**Keyboard flow:** `changepw-new` → `changepw-new-toggle` → `changepw-confirm` → `changepw-confirm-toggle` → `changepw-submit` → `changepw-signout-link`. The hidden username field is skipped.

**Password managers:** hidden `username` field with the phone number, both new fields `new-password`, real `<form>`, so Chrome can suggest a strong password and save it against the right number. This applies only when the device's Shared phone setting is off (DD-8); on a Shared phone the hidden username is left out, both fields use `autocomplete="off"` and the "don't save" hint shows.

**Targets:** ≥ `{spacing.target-min}` everywhere; Save `{spacing.button-desk}`; `{spacing.2}` between adjacent targets. Reflow at 320 CSS px and 200% text; nothing clips.

## Technical Notes

- **Blocking step:** the server marks the session "must change password"; every API call other than this one and sign-out is refused until the password changes, and every route redirects here (FR-54). Not only a client redirect.
- **What changes:** the new password is stored as a secure hash (NFR-6); the temporary password stops working; the User's other sessions, if any, end [ASSUMPTION].
- **Offline:** cannot be done offline (needs the server). The phone keeps the session in the must-change state; no floor actions can be queued before the password is set, so FR-41's "signed in online once" is satisfied only after this step [ASSUMPTION].
- **Language:** the User's saved language; on a first sign-in it is the language chosen on 10.1 (10.1 decision L4). No Language switch on this page (Open Question 5).
- **After success:** go to [10.3 Settings: Me](../10.3-settings-me/10.3-settings-me.md) with `?first=1` (first-sign-in form). This also satisfies the "one-time install prompt after first sign-in" from EXPERIENCE.md → Responsive & Platform.
- **Live regions:** polite (online status, toast) and assertive (errors) regions exist from page load.
